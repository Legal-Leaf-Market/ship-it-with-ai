Ship a first website

Build a one-page site for a fictional furniture repair shop. You’ll need a text editor and a way to host static HTML.

On this page

  1. Write the brief
  2. Build the first version
  3. Preview before publishing
  4. Publish and verify

1. Write the brief

Pick one visitor and one action. For this example, the visitor has a loose dining chair and wants an estimate. The action is an inquiry with a photo.

Business: Mill Street Furniture Repair (fictional)
Audience: Homeowners with loose or damaged chairs
Goal: Get repair estimate requests
Page: Headline, three services, pickup area, contact link
Constraints: Plain HTML, mobile-first, no invented reviews
Acceptance check: The estimate link opens an email draft

2. Build the first version

Ask your coding assistant to implement the brief in a single index.html. Supply business facts yourself and keep the first change small enough to review. Here’s a minimal starting file. Replace the example address with an inbox you control before releasing.

<!doctype html>
<html lang="en">
<meta charset="utf-8">
<meta name="viewport" content="width=device-width, initial-scale=1">
<title>Mill Street Furniture Repair</title>
<main>
  <h1>Get your favorite chair back in use</h1>
  <p>Loose joints, broken seats, and wood touch-ups.</p>
  <p>Ask about pickup in the Columbus area.</p>
  <a href="mailto:repairs@example.com">Ask for an estimate</a>
</main>
</html>

Want a head start? Edit and download the same example in the website builder.

Open the file in your browser. Add spacing, readable type, and one authentic photo only after the page structure works.

3. Preview before publishing

Put your source in a repository or save a dated copy. Open a preview and test it at phone and desktop widths. Use Tab to reach the estimate link, confirm its destination, and make sure the page still reads if the photo fails to load. Check every claim and link before release.

4. Publish and verify

Publish the tested folder to your static host, open the public URL in a private window, and repeat the estimate-link check. Send a clearly labeled test to an inbox you control and verify receipt. Save the previous working revision so you know what to restore if the release breaks.
